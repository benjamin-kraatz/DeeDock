# Line icon motions

With the Line icon style, a glyph plays a short motion when the pointer rests on its tile. This page describes the file that defines those motions and how to add one.

## Where things live

| File | Role |
| --- | --- |
| `DeeDock/Resources/LineIcons/LineIconMotions.json` | Every motion. Hand-written. |
| `DeeDock/Resources/LineIcons/LineIcons.json` | The glyph paths. Generated by `scripts/line-icons/build-line-icons.py`; do not edit. |
| `DeeDock/Dock/LineIcons/LineIconMotion.swift` | The model: decoding, easing, and the pose of each part at a point in time. |
| `DeeDock/Dock/LineIcons/LineIconMotionLibrary.swift` | Loads the JSON and picks the motion for a glyph. |
| `DeeDock/Dock/LineIcons/LineIconArtwork.swift` | Draws a posed glyph and plays the motion on hover. |
| `scripts/line-icons/motion-gallery.py` | Validates the JSON and writes a browser gallery of it. |

## Preview without building the app

```sh
python3 scripts/line-icons/motion-gallery.py
open build/line-icon-motions.html
```

Hover a tile to play it. The scrubber holds every glyph on one frame, and `?t=0.35` in the URL opens the page on that frame. `--all` includes every catalog glyph, and `--check` validates without writing a page. The script exits with a message for each problem it finds.

The page's JavaScript repeats the math in `LineIconMotion.swift`. If you change the format, change both.

## Parts

A motion moves parts of a glyph. A part is one subpath, which is one `M…` run in the catalog's path data. `s0` is the first stroke subpath and `f2` is the third fill subpath, counted across the glyph's path strings in order.

To see a glyph's parts, look it up in `LineIcons.json` and count the `M` commands, or print each part's bounding box with a few lines of Python. Custom glyphs come from `scripts/line-icons/custom/*.svg`. To animate a piece that is not its own subpath yet, split it in the SVG and rebuild the catalog.

Fill parts combine under the nonzero winding rule, as they do at rest. A cutout, such as the Discord eyes or the Ghostty cursor, is its own part. It stays a cutout while it remains inside the shape it is cut from, and scaling it to zero fills the hole.

## Format

```json
"lucide:trash": {
  "about": "The lid lifts on its hinge, then drops and rattles.",
  "duration": 0.8,
  "tracks": [
    {"parts": ["s3", "s4"], "rotate": [[0, 0], [0.3, 20, "out"], [0.55, 20], [0.75, 0, "in"]], "anchor": [21, 6]},
    {"parts": ["s3", "s4"], "y": [[0, 0], [0.3, -1, "out"], [0.55, -1], [0.75, 0, "in"]]}
  ]
}
```

The key is the glyph's catalog reference. `about` is one sentence for the gallery; the app ignores it. `duration` is in seconds, at most 3.

Each track animates one property of some parts.

| Field | Meaning |
| --- | --- |
| `parts` | `"all"` (the default), `"strokes"`, `"fills"`, or a list of part tokens. |
| the property | Its keyframes, as `[time, value]` or `[time, value, easing]`. Times run from 0 to 1 and must ascend. |
| `anchor` | The fixed point of a rotation, scale, or turn, as `[x, y]` in the 24-unit box. Defaults to `[12, 12]`. |
| `spread` | Staggers the targeted parts. The last part starts this far along the timeline after the first. The last keyframe time plus the spread must not exceed 1. |

| Property | Value | Rest |
| --- | --- | --- |
| `rotate` | Degrees, clockwise | 0 |
| `x`, `y` | Offset in catalog units; `y` grows downward | 0 |
| `scale`, `scaleX`, `scaleY` | Factor about the anchor | 1 |
| `turn` | Degrees about the vertical axis through the anchor, drawn flat. 360 is one coin flip. | 0 |
| `draw` | Share of a stroke drawn from its start. 0 hides the part. | 1 |
| `erase` | Share of a stroke removed from its start. Running it from 1 to 0 draws the stroke from its end. | 0 |

Easing shapes the change that arrives at a keyframe: `linear`, `in`, `out`, `inOut` (the default), or `back`, which overshoots by about a tenth of the change and settles.

A part holds a track's first value until that keyframe's time and its last value afterwards. Tracks apply in the order listed, so put a part's own track before a whole-glyph track that should carry it along. `draw` and `erase` affect stroke parts only. A squashed stroke keeps its line width, because the app scales the path and strokes it afterwards.

## Rules the app enforces

- Every track ends on its resting value. For `rotate` and `turn`, any whole number of turns counts. The app drops a motion that breaks this, because it switches back to the plain resting glyph when a play ends and the glyph would jump.
- The first frame may differ from rest. A draw-on starts from nothing.
- A motion that fails to decode costs only itself. The glyph then plays a fallback.

## Fallbacks

A glyph without its own entry plays one of the shared motions under `fallbacks`: the `stroke` list for glyphs that have strokes, the `fill` list for filled brand marks. A stable hash of the glyph's reference picks the entry, so an app always moves the same way. Adding or removing a fallback reshuffles which glyph gets which.

Fallbacks cannot name parts, because they apply to glyphs of any shape. Use `"strokes"`, `"fills"`, or `"all"`, with a `spread` to stagger.

## When a motion plays

`DockLineIconArtwork` plays the motion once when its tile becomes highlighted and stays so for 70 ms. Highlighted means the pointer is over the tile or the keyboard selection is on it. A hover that arrives while a play is running lets it finish. A tile that appears already highlighted does not play. Reduce Motion turns the motions off.

The dock, the Launcher, and the Open With list all draw through `DockLineIconArtwork`, so a motion shows up in each.

Planned, not built: playing the motion when an app opens. The player starts a play by bumping one counter, so a launch can use the same path.
