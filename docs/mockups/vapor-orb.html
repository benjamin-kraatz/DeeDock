Vapor mockup. While Finder is in front, Vapor looks at the folder it shows. Caches it recognizes float next to the orb as small bubbles. Click one to drop it in, or press Add All. Switch folders in the sidebar (DerivedData, SwiftPM, Downloads) and click a Dock app to put Finder in the background. You can still drag folders onto the orb by hand: ⌘-click picks several, ⇧-click a range. Click the orb to open it, then delete. Drag the orb around under the lamp at the top of the display and watch the highlight, rim light and shadow follow. Right-click the orb for its menu. Show or hide the orb from the DOKK menu at the top right of the menu bar (Tools › Vapor).

How Finder suggestions would work

  1. When Finder becomes active, or its front window changes folder or title, DOKK asks Finder for that window’s folder. AppMelt already does this through Apple Events. Nothing polls.
  2. DOKK lists only that folder’s direct children, off the main thread, and matches them against strong rules: node_modules, .next, .turbo, coverage, DerivedData entries, SwiftPM caches, .build next to Package.swift, target next to Cargo.toml, Pods, __pycache__.
  3. dist and build are recognized once you drop them in, but never suggested, because some projects commit them.
  4. Nothing goes in on its own. The orb panel never takes focus, so clicking a bubble leaves Finder in front.
  5. × hides suggestions for that folder until you open it again in Finder.

The lamp

  • Each display gets a virtual lamp just above the middle of its top edge. The highlight, rim light and caustic turn toward it, and the contact shadow falls away from it.
  • Highlights get fainter with distance from the lamp.
  • The angle is recomputed only when the orb moves, as a few transforms, so it costs nothing at rest.

How it would delete

  1. On Delete, each folder is renamed into a hidden .dokk-vapor folder on the same volume. A rename is one metadata write, so the Finder row disappears right away, whatever the file count.
  2. Undo during the 5 seconds renames it back.
  3. When the window closes, a background task removes the files at utility priority, the same work rm -rf does. It calls removefile() in-process, with several workers on separate subtrees, instead of starting a shell.
  4. If DOKK quits midway, it finishes clearing .dokk-vapor on its next launch.

What it refuses

  • Home, the volume root, and standard folders: Desktop, Documents, Downloads, Library, Applications, System.
  • Anything inside a system location, plus files on volumes DOKK can't write to.
  • Folders it can't identify are still accepted, but they get an orange Not a known cache tag.

Not real in this mockup

  • Sizes and file counts are fake. In the app they come from a background walk that runs as each folder lands in the orb.
  • Kind tags such as “npm packages” come from simple name and marker rules: node_modules, DerivedData, .build, target next to Cargo.toml, and so on.
