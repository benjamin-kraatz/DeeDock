# Flix Files

Flix Files (DEE-163) is an activity stream of what you opened, downloaded, saved, and screenshotted, built to be dragged from. Its home is a dock tile; the panel opens above the tile, at the pointer with Control-Option-Command-F, or under an optional menu bar item. The approved designs are [`mockups/flix-files-v2.html`](mockups/flix-files-v2.html) (the concept) and [`mockups/flix-files-ai.html`](mockups/flix-files-ai.html) (the target UI with every ✦ feature). How each feature behaves for a person is in the [guide](GUIDE.md#flix-files).

This document covers phase A (the data, sources, tile, panel, drag, settings, and every ✦ surface wired to a slot model), phase B1 (window reading and Fits this window, the tile's pill, upload conversion, the sensitive file guard, and web links), phase B2's providers, in [Phase B2: intelligence](#phase-b2-intelligence), phase C's [analytics](#analytics), and [Flix Pick](#flix-pick) beside other apps' Open and Save pickers (DEE-164, [`mockups/flix-pick.html`](mockups/flix-pick.html), style Tuck).

### Data

`FlixHistory` is DOKK's own history; Spotlight and the folder watcher only feed it. Every source produces `FlixActivityEvent`s, which `FlixHistoryDocument.record(_:)` merges:

- One item per standardized path (or page address). A newer event changes the item's activity and moves it to the top; an older one only fills in missing details. Identity, flag, and first-seen date survive, so selection and phase B's annotations stay attached.
- When two sources report the same moment, a download beats "new", which beats "saved".
- **Remove from Flix Files** leaves a tombstone: the item returns only with activity newer than its removal. Undo restores it.
- **Clear History…** keeps one date, `clearedAt`, which survives the clear and is saved with the history: no source event dated at or before it is recorded. Spotlight replays the last 30 days at every launch, so without it cleared items would come back.
- At most 5,000 items, oldest unflagged first; flagged items never age out. Noise is capped separately at 200, so a build folder cannot push real activity out.
- A finished download replaces its partial entry (`Report.pdf.crdownload` → `Report.pdf`).
- Each file row records which file it lists (`FlixItem.fileIdentity`, a `FlixFileIdentity`: volume and inode, plus size and modification time for files). The folder watcher reads it with the event; a newer event without one (Spotlight, an app) clears it, and the coordinator's background pass (`captureMissingIdentities`) reads it off the main actor, 300 rows at a time, only where the read policy allows. See [File commands](#file-commands).
- A download's page never reaches a file row from an event, only its host. The link tracker attaches the full page after verifying the download (`attachVerifiedSource`, which sets `sourcePageIsVerified`); see [Web links](#web-links).
- `record(batch:)` merges a whole batch (Spotlight's gather and updates, the watcher's coalesced batches) by key and then sorts and enforces the caps once, with the same results as merging the events one by one: the clear cutoff, tombstones, flags, the noise cap, and partial downloads behave alike (`FlixHistoryBatchTests`). Items of the same moment sort by key, so both paths give one order. The only difference is at the 5,000-item edge, where sequential merging could drop an old item mid-batch and re-create it under a new identifier.

The history and the library are two JSON files in `~/Library/Application Support/DDock/Flix/` (`Flix-dev/` for a development build, the split Lookout makes). Writes coalesce for 0.8 seconds and run on a utility queue; quit flushes them. An unreadable file is moved aside as `history.unreadable-<time>.json` and Flix Files starts fresh, so a broken file never stops it.

Settings are JSON under `flix.settings.v1` in DOKK's defaults. Missing keys decode to their defaults.

### Sources

- **Opened** (`FlixSpotlightSource`): a live `NSMetadataQuery` on `kMDItemLastUsedDate` over the last 30 days, folders included and app bundles left out. The first gather seeds the newest 300; updates report only what changed. Each gather or update reaches the history as one batch (`record(batch:)`). Everything comes from Spotlight's attributes (path, name, type, size, `kMDItemIsScreenCapture`, `kMDItemWhereFroms`), so it never reads a file and needs nothing off the main actor; the rows' file identities are read later by the background pass.
- **New, saved, downloaded** (`FlixFolderWatcher`): one FSEvents stream with file-level events over the watched folders DOKK may read. Events coalesce per path for 1.2 seconds. A file born in the last five minutes is a download when it carries `kMDItemWhereFroms` or sits in Downloads, otherwise new; an older file that changed is saved. Screenshots come from the `kMDItemIsScreenCapture` attribute. Hidden files, package internals, partial downloads, noise, and symbolic links are skipped; every event path is checked against the read policy again before it is read (a folder that became a link since the stream started is not read through), resource values describe the item itself, and extended attributes are read with `XATTR_NOFOLLOW`, so nothing the watcher reads follows a link. Each event carries the file's identity.
- **Apps**: `DockCoordinator`'s existing activation callback; each app is recorded at most every five minutes. Finder and DOKK are left out.

A download's page goes through `FlixURLSanitizer` (`FlixPaths.sourcePage`: no query, fragment, or sign-in details, and nothing at all for a credential-bearing address), then `FlixSourcePolicy` decides what may be kept, in `FlixCoordinator.receive` before the history or the link tracker sees the event. The history takes only the host, for the row's "Downloaded from example.com" (nothing for an excluded site). With **Track web links** on and the site not excluded, the page is the link tracker's candidate: it is stored on the file's row only once the tracker verified the download came from a normal window showing that very page (see [Web links](#web-links)), and the row is marked `sourcePageIsVerified`. The same policy runs over the stored history at launch and whenever web links, the excluded sites, or the banking and health switch change: a stored page without the verified marker (saved by an earlier build) is scrubbed to its host, and turning web links off strips verified pages too. Stripping is one-way.

### Folder access

`FlixReadPolicy` decides what may be touched on disk. Desktop, Documents, Downloads, iCloud Drive, cloud storage folders, and other volumes are protected (`LookoutFolderChoice.needsPrompt`): reading one makes macOS show its Files and Folders prompt. A protected path is readable only inside a watched folder you allowed with **Allow…** (in Settings or on the panel's card) or inside a folder Lookout's setup already read with your permission, since macOS grants per app. Thumbnails, file icons, the watcher, captions, the sensitive guard, conversions, Ask Robi, and file commands check the policy; otherwise rows draw the type's icon. No background work can cause a prompt.

None of this runs on the main actor, except checks of a path's spelling (`FlixReadPolicy.spellingIsReadable`), which never touch the disk. The policy's full check examines every component with `lstat`, and a folder on a network share that went away can make one `lstat` wait for seconds, freezing the dock. So the tile's and the rows' thumbnails and file icons resolve the path in the background (`FlixReadPolicy.readableURLInBackground`, `FlixIconProvider.loadIcon`) and draw the type icon until then; the sensitive guard, captions, Ask Robi, Tidy, and conversions queue by spelling and resolve on their workers; the watcher resolves its folders on its own queue; dropped files are read on `FlixFileWorker`; and folder names come from the path (`FlixFolderNames`: the last component, with the localized names of home folders such as Desktop looked up once in the background, and only for folders the policy allows).

`canRead` follows symbolic links the way `realpath` does, but safely: the spelling is checked first, then each component is examined with `lstat` only once the place it leads to is known to be readable, a link is read with `readlink` and its target spliced into the rest of the path, and the new destination must pass the spelling check before anything under it is touched (at most 16 links). So `~/Projects/docs → ~/Documents` is as unreadable as `~/Documents` itself, and a link into an allowed folder stays readable. The analyzer also checks the file's folder before listing it for a free name.

Protected folders and allowed roots are compared without regard to letter case or Unicode normalization (`FlixPaths.folded`), because the default volumes are case-insensitive: `~/documents/tax.pdf` and a decomposed spelling reach `~/Documents` too. Folding can only add protected paths, never remove one. Lookout's own `LookoutFolderChoice.needsPrompt` still compares by spelling; Flix checks both.

A check is a moment in time, and background work reads later. So every background read re-validates at the point of use:

- Direct reads (the sensitive scanner, captions and facts, Ask Robi's file reading, conversions) open the file through `FlixSafeFile`: the policy resolves the path again right then (`FlixReadPolicy.resolve`), the resolved, link-free path is opened with `O_NOFOLLOW_ANY` (so a component that became a link since fails the open), FIFOs and devices are refused, and the descriptor's real path (`F_GETPATH`) is checked once more. Readers decode the descriptor's bytes, so PDFKit, ImageIO, and AppKit's importers see exactly the checked file. The bytes are copied into memory with `pread` in 4 MB chunks (`read(upTo:)`, `contents(maximumBytes:)`), never mapped: a mapping stays backed by the file, and a share that disconnects or an app that rewrites or truncates the file while a decoder walks it would crash DOKK with `SIGBUS`. A failed or short read is an error (`FlixSafeFile.ReadError`) that the reader treats as an unreadable file. Each use has its own cap on what it holds: pictures and PDFs for captions and facts 64 MB, the sensitive scanner 60 MB, pictures for a conversion 100 MB, RTF and other documents 25 MB, text 4 MB for conversions and 64 KB or 256 KB for captions and the scanner. An RTFD package's files are read with `FileWrapper`'s `.withoutMapping`.
- URL-based reads (Quick Look thumbnails and icons for rows and the tile, file stamps, folder listings for free names) take `FlixReadPolicy.readableURL`, the path resolved right before the call.
- An RTFD package is a folder: its contents are listed first without following links (a package holding a link is not read), then the importer reads the checked path. That read and the URL-based ones keep a narrow window between check and use.

### File commands

Trash, Move (a folder favorite, **✦ Move to …**), Rename (the sheet, **✦ Rename**), Tidy, and Undo run on `FlixFileWorker`, a serial dispatch queue off the main actor, in the order they were asked, so a long copy to another volume never freezes the dock and an Undo always runs behind the move it undoes. A block that started finishes (a half-done move cannot be cancelled safely); its result is applied to the history by item identifier when it arrives, even if the panel closed. A move still running after 0.45 seconds shows a "Moving “Invoice.pdf”…" toast (Tidy: "Tidying up…") until its result replaces it.

Before acting, each file is checked against its row (`FlixFileOperations.check`): the file at the path must still be the one the row recorded. A file replaced since (a new download with the same name, an app's safe save, a file put there by hand), or gone, is left alone; its row is refreshed (it takes the identity of what is there now, or leaves the history when nothing is) and the toast says "… changed since it was listed, so nothing was done". A row that has no identity yet (just recorded from Spotlight, or in a folder Flix may not read) is treated the same way, conservatively: the first attempt records what is there and says "… was just checked, so nothing was done yet"; the second goes ahead. Trash checks on the worker, then hands only the confirmed files to `NSWorkspace.recycle` (Put Back still works). The check and the operation are separate system calls, so a file swapped in the instant between them is not caught. Undo keeps its own check: a file goes back only when it is still the one moved and its old place is free.

### Tile

`DockRenderSlot.flix` sits in the trailing utilities after the Notification Feed and is reorderable like them (`dockUtilityOrder`). `DockFlixButton` reads `FlixTileState` from `DockInteraction.flix`, so a new item redraws the tiles alone. A plain drag carries the newest item through `FlixDragSession`; Option-drag moves the tile (`DockUtilityMoveModifier.movesOnlyWithOption`, the Shelf's split inverted). A file drag from Finder onto the tile goes through `DockDragCoordinator` (`DockUtilityDropTarget.flix`) and is kept; the tile refuses Flix's own items. The badge counts downloads and new files since the panel was last opened.

### Panel

`FlixPanelController` owns a borderless key panel at the floating level, the body plus a 30-point transparent margin for the shadow. Anchored, it sits 12 points above (or beside) the tile and follows it when the dock moves; at the pointer, its top-left corner sits a little up and left of the pointer. Both clamp into the display's visible frame (`FlixPanelGeometry`, tested with negative origins). Opening goes through `ExplicitWindowPresenter`, so the panel becomes key and search gets a field editor.

Before anything takes focus, the coordinator captures the app and window in front (`FlixFrontmostContext.capture`): process, bundle identifier, app name, and the frontmost window's number from the window server's list, with its title only when Screen Recording is granted. `FlixPanelState.frontmost` holds it for the panel's lifetime.

Monitors exist only while the panel is on screen: a local key monitor that offers every key to `FlixPanelState.handleKey`, local and global mouse-down monitors for outside clicks (a dock click closes the panel and is consumed), and an observer that closes it when DOKK stops being active. None of them closes the panel during a drag out or while Quick Look is up. An anchored panel registers as the `.flix` popover, which closes the other popovers and holds the docks revealed.

### Dragging out

Rows, the selection, a Thread card, and the tile start a `FlixDragSession`: file URLs, web URLs for links, and a private type listing item IDs. As the pointer leaves the panel it fades to 6 % and lets the pointer through; after a drop outside it closes unless pinned or set to stay open; a cancelled drag brings it back. A drop on a dock app opens the files there, as any file drag does.

Two hooks run at drag start, because macOS never tells a drag source where the drop will land:

- **Substitution.** `FlixIntelligence.dragPlan(for:context:)` asks `FlixDragIntercepting.plan(for:context:fits:)`. Its `substitutions` replace an item's file on the pasteboard (a PDF made from an image for a PDF-only portal), and its `label` is drawn under the first drag icon (`FlixDragLabelImage`). It is synchronous, so conversions must exist already; browsers read file URLs, not promises. A panel drag substitutes only while the window the panel read is still the one in front (`FlixFrontmostContext.isStillInFront`): the copies are for that upload. DOKK's own destinations never receive a copy: `FlixDragSession.originalURLs(for:on:)` maps copies back to their originals for the dock (`DockDragCoordinator`'s payload: the Shelf, the Trash, app tiles, actions, the launcher, window file handoff) and for folder and drive tiles (`FolderFileDrop`), and `FlixDragSession.fileURLs(on:)` reads and maps a drag's file URLs for every other DOKK target: Hub Files panes, columns, and tabs (`HubFilesInteractionView`), the Hub Files sidebar (`HubFilesSidebarModel+Drag`), the picture search well (`HubFilesModel+Pictures`), the Hub Apps tab (`HubAppsFileDrop`, through `originalURLs(forDropped:)` on the drag pasteboard), and Vapor (`VaporDragPasteboard`). Sidebar favorites take item identifiers, so they always get originals. A temporary copy is therefore never staged, moved, copied, adopted, or trashed, and Flix's cleanup of its copies cannot delete anything DOKK kept.
- **Confirmation.** `FlixIntelligence.dropConfirmation(for:context:)` asks `FlixDragIntercepting.confirmation(for:context:)`, then falls back to phase A's own rules: an item annotated as sensitive (while the guard is on, and only while no drag provider is installed, since B1's provider answers that question itself), then an older version with a newer one in the history. A question stops the drag and shows a dialog in the panel. An answer is scoped (`FlixDropApprovals`): it lets drags past that one question kind (sensitive, or older version) for that item, with the file identity its row listed and, for a version answer, that newer version, for 30 seconds. **Use Newer** grants nothing: it swaps the newer item in, and the new set is evaluated again at once, so a newer version that is itself flagged asks its sensitive question next. Likewise a flagged older version asks both questions in turn. When nothing is left to ask, the toast says "Drag it again to send it". A tile drag that needs a question opens the panel with it.

- **Stale rows at DOKK's destructive drops.** `FlixDragSession` keeps the file identity each dragged row listed when the drag began. The Trash compares them with the files at their paths in the payload's background read (`DockDragCoordinator.load`, `FlixDraggedFiles.changed(among:)`), refuses the drop when one differs (replaced, saved again, gone, or never identified), shows the Trash's failure message naming the file ("“Invoice.pdf” changed since Flix Files listed it…"), and checks once more off the main actor right before recycling. A folder or drive tile that moves (Shift) checks before the first file moves and fails the whole batch with the folder drop's message (`FolderFileDrop.copy(verifying:)`); copies are not checked, since they leave the file in place. A drop on a sidebar folder favorite moves with the identities the drag captured (`FlixFileOperations.move`). Each refusal refreshes the rows' identities, off the main actor, so dragging again acts on the file as it is now. Hub Files panes and Vapor read the originals but do not compare identities.

## Intelligence slots (contract for phase B)

`FlixIntelligence` (`@Observable`, main actor) is the only thing the views read for ✦ features. With no providers, every slot stays empty and its surface does not appear; plain filters and name search keep working. Phase B assigns `flix.intelligence.providers` (a `FlixIntelligenceProviders` struct of optional existentials); `FlixEngineMonitor` keeps `flix.intelligence.engines` current.

| `query` | `FlixSearchProviding` | "Ask in your own words", Understanding…, tokens, "by meaning" chips |
| `threads` | `FlixThreadProviding` | ✦ Threads sidebar section, Thread card, Show Thread |

Every slot task is cancelled when its replacement starts, and a generation check drops stale results; `panelClosed()` cancels the panel's tasks and `stop()` all of them. Providers read the intelligence and link switches from `flix.settingsStore.settings` (`suggestsForFrontWindow`, `showsFitsOnTile`, `writesCaptions`, `groupsThreads`, `suggestsFolders`, `guardsSensitiveFiles`, `learnsDragDestinations`, `tracksLinks`, `tracksPagesYouRead`, `excludesSensitiveSites`, `excludedSites`, `fetchesSiteIcons`); `FlixIntelligence.settings` mirrors them and hides disabled surfaces.

Link items are recorded with `flix.history.record(_:)` and a `FlixActivityEvent` whose `link` is set, whose kind is `.link`, and whose activity is `.link`. Rows draw them with a site monogram and the host.

Three additions serve phase B1 and are open to B2:

- `FlixIntelligence.reviseAnnotation(for:_:)` changes one item's annotation in place. The sensitive guard writes its verdicts through it as they arrive. The sensitive fields (`isSensitive`, `sensitiveReason`) belong to the guard: when the coalesced `FlixAnnotationProviding` pass merges fresh annotations, it keeps them.
- `FlixIntelligence.slotsChanged` fires when the tile's pill or an annotation changes, so the coordinator redraws the tile (`FlixCoordinator.refreshTile()`), which is not a SwiftUI observer of the slot model.
- `FlixContextServices.start(with:)` installs its providers by mutating `intelligence.providers` (`fits`, `drag`) and leaves every other slot as it found it. Other phases should install theirs the same way.

## Window reading and Fits this window

`FlixContextServices` (phase B1) owns the parts below. `FlixCoordinator.live()` creates it; the coordinator calls it on start, stop, settings changes, history changes, recorded events, the panel opening, and drops. Previews and tests run without it.

### Reading the window

`FlixFrontmostContext.capture` records the app and window in front before the panel takes focus. When the panel opens, `FlixIntelligence.readWindow` asks `FlixFitsProvider.fits(for:candidates:progress:)`, which runs `FlixWindowReader`'s chain and reports each step, so the card's chain label and shimmer follow along:

1. **Accessibility**: `RobiWindowText.read` on the app's focused window, 0.6 seconds and 12,000 characters at most. Electron and Chromium apps build their web tree only for assistive apps, so `FlixWebTree.enable` turns it on for this one read and `restore` turns it off straight after, cancelled or not; both run detached with a 0.2-second messaging timeout, never on the main actor. Skipped without Accessibility permission.
2. **Vision**: when Accessibility found too little, `RobiCapture.image(windowID:)` captures that one window and `recognizeText` reads it. The window number is the window-server window whose bounds match the app's focused accessibility window (both in global top-left points), else the one the capture recorded. Skipped without Screen Recording (`CGPreflightScreenCaptureAccess`, which never asks). The picture stays in memory.
3. **Apple Intelligence**: when Vision also found too little and the system model is available with the `.vision` capability, the picture itself goes to the model.

"Too little" is `FlixWindowTextPolicy`: fewer than eight words of three or more letters, about one sentence. Toolbar labels count, which is why the bar is a sentence and not a word.

### Understanding it

`FlixDemandInterpreter` asks Apple Intelligence (a `@Generable` `GeneratedWindowDemand`: wanted items with the window's own phrase and name keywords, accepted file types, a size limit, and the page kind) with a fresh session, greedy sampling, 320 tokens, and a 10-second limit. The window text is untrusted and the instructions say so. Without Apple Intelligence, or when it fails, `FlixDemandFallbackParser` applies plain rules: the objects of request verbs ("attach", "upload", "send", "anhängen", "hochladen"…, with German's verb-last order), type words on a line with a limit word ("PDF only", "Nur PDF"), size limits ("max 5 MB", "bis zu 1,5 GB"), and upload words for the page kind. The app's category (`FlixAppCategory`, from Launch Services' `https:` and `mailto:` handlers and `LSApplicationCategoryType`, never the name) says mail or chat.

These Apple Intelligence calls are not sent to AI observability at all, not even as metadata: their input is the window's text or picture. The same holds for the sensitive scanner's look at a picture. Every other Flix Files model call reports metadata only (see [Privacy](#privacy)).

### Matching

`FlixFitRanker` scores the newest 1,500 items against each wanted phrase with a `FlixFitScoring`. Today that is `FlixKeywordFitScorer`: the phrase's keywords against the item's name (split on separators and case changes), phase B2's caption and facts, its folder, and its source host, with English and German synonyms ("agreement" finds "Vertrag"), word starts and ends for compounds, kind words ("screenshot", "photo") matched against the item's kind, and time words ("this month") against its date. A kind or time word alone never matches, so "the moodboard" is not answered by any picture. Scores below 0.5 are dropped. Each phrase first gets its best item, then the best remaining scores fill up to three. Upload pages skip folders, apps, and links, and every page skips files it would refuse that no conversion can fix.

For the panel, while Lookout runs, `FlixBlendedFitScorer` adds meaning: `FlixFitsProvider` embeds each wanted phrase once (`FlixSemanticIndex.embed(_:)`), compares it with the candidates' text-averaged file vectors (`vectors(for:)`, cached), and keeps the files that stand out (`FlixSemanticScoring.ranked`, cosine at least 0.30 and z ≥ 1.0). A similarity becomes a 0–1 meaning score between 0.30 and 0.55 and is blended as `max(keyword, 0.6 × meaning + 0.4 × keyword)`, so a word match keeps its score and a match by meaning alone passes the 0.5 bar only near 0.55. Picture vectors are left out (text-to-picture scores run on another scale). Without Lookout, or for files it has not read, the keyword scorer answers alone. The tile's count never embeds: it matches words only. Drag memory's guess for the app in front (`likelyItem(for:among:)`) adds 0.04 to that item's passing score, enough to win a tie or near-tie in the card and in the tile's count, never enough to make a non-match pass; rows without a reason of their own show drag memory's "↺ you've sent PDFs here before".

Ranking runs off the main actor. Readings are cached per `FlixWindowKey` (process, window number, accessibility title), up to 24 windows, so opening the panel again on the same window only re-ranks, and a new page or conversation reads afresh. The card's label is the page's host in a browser (`FlixBrowserPageReader`, read for the label only), else "App · title".

### The tile's pill

`FlixFrontWindowObserver` keeps one `AXObserver` on the frontmost app for focused-window and main-window changes and on its focused window for title changes, plus NSWorkspace's activation notification. Bursts settle for 350 ms. Nothing it asks of another app runs on the main actor: creating the observer, registering notifications, and reading the focused window are IPC, so they run on `FlixAXThread` (one dedicated thread with its own run loop, where the observer's source and callbacks live) with a 0.2-second messaging timeout per element, and only after an app switch has settled, so flicking through apps costs no IPC. Each switch bumps a generation: work queued for an earlier switch is skipped on the thread, and callbacks from an app no longer in front are dropped on the main actor. Without Accessibility permission only app switches arrive. It runs only while **Show "fits here" on the tile** or **Track web links** is on, and `stop()` removes the workspace observer and, on the thread, the notifications and the run-loop source. On each change, `FlixFitsProvider.tileFitCount` reads the window's accessibility text without turning on any web tree, applies the plain rules (never a model, never a capture), and counts the fits. A complete panel reading of the same window is used when cached.

## Upload conversion

When a window's demand has accepted types or a size limit, `FlixConversionPlanner` decides per item from its type and size, without reading it:

| Original | Window takes | Result |
| --- | --- | --- |
| A picture ImageIO reads (HEIC, PNG, TIFF, WebP, JPEG, GIF…) | PDF | One-page PDF wrapping a JPEG (passed through, so the PDF is barely larger) |
| A multi-page TIFF or multi-image HEIC (up to 30 frames) | PDF | One page per frame, the size limit shared between them |
| That picture | JPEG or PNG, not PDF | JPEG, else PNG; a picture with several frames is declined |
| A picture over the limit | its type or JPEG | Scaled down (and re-compressed for JPEG) until it fits |
| Plain text, Markdown (laid out as written), flat RTF | PDF | A4 pages laid out with Core Text, 54-point margins, unless an RTF file holds something that layout leaves out (below) |
| Word (`.docx`, `.doc`), OpenDocument text, RTFD, HTML, web archives, Pages, Numbers, Keynote, a PDF over the limit, a zip, anything else | — | Unchanged; not suggested in Fits |

Word, OpenDocument, and RTFD files are never converted automatically. AppKit's importers leave out footnotes and endnotes, text boxes, comments, tracked changes, fields, and more, and no check of a file's parts can vouch for all of them; RTFD exists to carry attachments, and its inner RTF is not checked. They are still read for the sensitive guard and for captions.

A copy is written only when it shows everything the original does (`FlixConversionFidelity`); otherwise the converter declines (`ConversionError.wouldOmitContent`) and the original goes out, with no label: a portal refusing a file is better than one silently receiving less. Declined are an animation (GIF, animated PNG or WebP, HEIC sequence) in any format, several frames for JPEG or PNG, more than 30 frames, and an RTF file that holds, as whole control words read from its raw bytes before importing (`FlixConversionPlanner.documentParts`, `rtfControlWords`), pictures (`\pict`, `\shppict`), objects (`\object`), headers or footers (`\header`, `\footerl`, …), footnotes or endnotes (`\footnote`), shapes and text boxes (`\shp`, `\shptxt`, `\do`, `\dptxbx`), positioned frames and paragraphs (`\posx…`, `\posy…`, `\absw`, `\absh`, `\phmrg`, `\pvpara`, …), comments (`\annotation`, `\atnid`), or tracked changes (`\revised`, `\deleted`); the bytes checked are the bytes imported. Matching whole words keeps the section formatting Word writes into every RTF file (`\headery708`) from counting as a header, and an escaped backslash in the text is not a control word. As a second line, attributed text holding any attachment (`NSTextAttachment`) is declined. `FlixConversionStore` remembers a declined file until it changes and does not try it again.

`FlixConversionStore` makes the copies before a drag: as soon as a window's demand is known it converts the Fits rows, the selected rows, and the first six rows of the list (on a tile reading, the newest item), two at a time, off the main actor, in tasks it owns. Only files `FlixReadPolicy` allows are read. Copies go to `…/T/DOKK Flix Conversions/<random>/<original name>.<ext>`; copies older than two hours are removed when more are prepared, and the folder is emptied when Flix Files starts and stops. A copy is used only while the original's modification date still matches: each prepare reads the originals' dates off the main actor (`FlixContentReader.stamps`, which also resolves the path through the policy) and drops a stale copy or retries a changed declined file; the converter records the date of the file it actually read; and at drag start, which answers from memory, a row whose identity records a newer modification than the copy's source does not get the copy.

At drag start `FlixDragInterceptor.plan` substitutes the ready copies and labels the drag ("✦ Upload as PDF · 1.2 MB", "✦ Upload as PDF · 2 converted", "✦ Upload smaller · 4.1 MB", "✦ 3 converted for upload"). A Fits row shows the same copy as a chip ("as PDF · 1.2 MB"), which appears when its copy is ready (`FlixConversionStore.version` is observed). An item whose copy is not ready goes out unchanged. Markdown is laid out as written, syntax included, so a link's address or an image's source is never dropped. Copies carry no metadata (no location, no camera).

Every conversion runs off the main actor (`FlixFileConverter.convert` is `@concurrent`) and is bounded: pictures are read up to 100 MB and decode through ImageIO's thumbnail path at most 4,096 pixels long; plain text and Markdown up to 4 MB; RTF up to 25 MB; a text over two million characters is refused rather than laid out. RTF is imported from the checked bytes with its type named, so a file is never sniffed into HTML, and every read goes through `FlixSafeFile` (see [Folder access](#folder-access)). `FlixDocumentImport` (RTF, RTFD, Word, OpenDocument, always typed) serves the sensitive scanner and the caption reader. HTML and web archives are not converted at all: AppKit's HTML importer needs the main thread and loads a page's external images, style sheets, and frames. The sensitive scanner and the caption reader use the same typed import.

## Sensitive file guard

`FlixSensitiveGuard` checks files once, in the background, while **Sensitive file guard** is on. Every history change queues new files (images, screenshots, documents, others), newest first, at most 300 per pass; one worker task reads one file at a time at utility priority. Verdicts are cached by path and modification date in `sensitive.json` next to the history; a file written after its check is checked again. Queueing looks only at memory: the cached verdicts and the path's spelling (`spellingIsReadable`). The worker opens each file through `FlixSafeFile`, where the policy's full check (the `lstat` walk) runs, off the main actor; the guard never makes macOS ask for folder access. A path the worker could not open is not queued again until its item has a newer date or the policy changes. A cached verdict is reported without touching the disk. The rules give the first, fast verdict; once Apple Intelligence has read a document (see [Annotations](#annotations)), its kind settles it for that file version (`FlixSensitiveRules.verdict(rules:documentKind:)`): an ID or a bank or card statement is flagged, a payment document is not for the bank details it prints, and a secret the rules found stays flagged. The guard never waits for the model. Invoices, receipts, quotes, and reminders (`FlixSensitiveRules.paymentWords`) are not flagged for an IBAN or bank words, since they print the account to be paid and are made to be passed on; account statements (`accountWords`) and card numbers still are. `FlixSensitiveDocument.currentVersion` 2 checks every file again under this rule; paths marked **Not Sensitive** stay cleared.

A drag of a flagged item carries a blurred picture with a lock (`FlixSensitiveImage`), from the panel and from the tile, so the file is not readable under the pointer either.

`FlixSensitiveScanner` stops at the first verdict: the name (`.pem`, `.key`, `.p12`, `.kdbx`, `.keychain-db`, `id_rsa`, `.env`, "passwords"…); text (plain text up to 256 KB, a PDF's first three pages, RTF and Word documents); Vision text recognition on pictures and on a scanned PDF's first page; and, for a picture with at least two lines of text that no rule matched, Apple Intelligence's look at it (identity document, bank details, secret, or something else; 12 seconds at most, not sent to AI observability). `FlixSensitiveRules` holds the text rules: a passport or ID machine-readable zone, two ID words (English, German, French), an IBAN that passes its mod-97 check, two bank words ("account number", "routing number", "BIC", "Kontonummer"…), a Luhn-valid card number next to "card", and PEM, OpenSSH, PGP, and PuTTY key markers.

Verdicts reach `FlixIntelligence.reviseAnnotation`, which sets `isSensitive` and `sensitiveReason`; rows, the tile (`refreshTile`), and VoiceOver read them. Switching the guard off clears every blur it set. At drag start `FlixDragInterceptor.confirmation` asks for every drag holding a flagged file, whichever app is in front: macOS does not tell a drag source where the drop will land, and with Finder in front the file can still end up in a browser or a chat. The question names the window in front only when it belongs to a browser, a mail app, or a chat app (`FlixAppCategory.isOutside`). After an answer, drags past that question for that file go ahead for 30 seconds (see [Dragging out](#dragging-out)). The dialog offers **Send Anyway**, **Not Sensitive** (stored by path in `sensitive.json`; that file is never flagged again, even after it changes), and **Cancel**.

A browser is an app that opens `https:` addresses (Launch Services). Pages are read through Accessibility only when the observer reports a window change while a browser is in front, and again when a dwell ends, to confirm the same page is still showing; nothing polls, and the dwell timers are single sleeping tasks cancelled by the next change. `FlixBrowserPageReader` walks at most 700 elements or 0.3 seconds of the focused window, off the main actor, with a 0.15-second messaging timeout on every element, and never sets `AXEnhancedUserInterface`. The address comes from a web area's `AXURL`, else from the first text field whose value looks like an address (the omnibox).

Everything automatic needs a window that reads as **normal**, and normal needs positive evidence (`FlixBrowserWindowEvidence`): no private marker ("Incognito", "Inkognito", "InPrivate", "Private Browsing", "Privater Modus", or the whole word "Private"/"Privat"…) in the title or any label, *and* the region where that browser shows its private indicator was read completely. The walk visits a toolbar (`AXToolbar`) to its end the moment it finds one, before the rest of the window, so the budget runs out elsewhere; a toolbar counts as read only when every descendant was visited and every privacy-relevant read inside it — the role, the title, description, and help labels, and the child list, of the toolbar and each descendant — answered without an error (`FlixBrowserPageReader.attribute` keeps the Accessibility status, telling "none" from "failed"). Labels are capped at 300 outside toolbars only, so a window with many tabs still has its toolbar's labels read. Anything less — the budget cut the toolbar short, a role, label, or child list read failed or timed out, a web area sat inside the toolbar (its inside is never read), the address sat outside a toolbar, the window's title could not be read, no title for Firefox — is unknown, and unknown is treated as private.

| Browser | Address | Region that must be read completely | Automatic tracking |
| --- | --- | --- | --- |
| Safari, Safari Technology Preview | Web area `AXURL` | None: no private-window signal DOKK could verify | Off: saves and URL drops only |
| Chrome, Edge, Brave, Vivaldi, Opera, Chromium, Helium, Arc, Comet, other Chromium builds | Omnibox value (scheme added), or `AXURL` when the web tree is already on | The toolbar holding the omnibox, where Chrome's "Incognito", Edge's "InPrivate", and Brave's "Private" badge sit next to the profile button | On; unverified by hand, including localized UIs and Arc's sidebar layout (an Arc window without an `AXToolbar` around its address reads as unknown) |
| Firefox, Zen, LibreWolf, Floorp, Waterfox | URL bar value, or `AXURL` | The toolbar holding the URL bar, and the window title, which Firefox ends with "Private Browsing" in a private window | On; unverified by hand |

`FlixURLSanitizer` decides what of an address may be stored, conservatively, for every trigger including deliberate saves. First, invitation, meeting, short-link, and share-secret addresses are never stored, however short (`FlixShareLinkDenylist`, a maintained, best-effort list): whole hosts such as `discord.gg`, `chat.whatsapp.com`, `wa.me`, `signal.group`, `meet.google.com`, `join.slack.com`, `calendly.com`, `whereby.com`, the shorteners (`bit.ly`, `t.co`, `tinyurl.com`, `goo.gl`, `ow.ly`, `buff.ly`, `rebrand.ly`, `is.gd`, `cutt.ly`, `lnkd.in`, `aka.ms`, `forms.gle`, …), and file shares (`wetransfer.com`, `we.tl`, `docsend.com`, `1drv.ms`, `mega.nz`, `mega.io`, `mega.co.nz`, `*.notion.site`, `db.tt`, `*.dropboxusercontent.com`, `*.pcloud.link`, `filedn.com`, `drive.usercontent.google.com`); routes such as `discord.com/invite`, `t.me/+…` and `/joinchat`, `zoom.us/j`, `/my`, `/s`, `/w`, `teams.microsoft.com/l/meetup-join`, `*.slack.com/shared_invite`, `icloud.com/share`, `/iclouddrive`, `/photos` and the other iCloud shares, `/attachment` (Mail Drop), `/sharedalbum`, Box's `/s`, `/v`, `/shared`, and `/f`, Dropbox's `/s`, `/scl`, `/sh`, `/t`, `/l`, and `/request`, MediaFire's `/file`, `/file_premium`, `/folder`, `/view`, `/download`, `/i`, the bare `/?<key>` and `/<key>` forms, and every MediaFire subdomain but `www` (download servers, the web app's folder keys), pCloud's `/publink`, OneDrive's `/redir`, `/embed`, `/download`, and `?redeem=`, Google Docs published to the web (`/document/d/e/…`) and `/uc` downloads, and SharePoint and OneDrive sharing links (`/:w:/g/…`, `/:x:/s/…`; `/:w:/r/…` names the document and is kept); the words `invite`, `join`, `j`, `s`, `share`, `my`, `meet`, `w` anywhere in the path on a known messaging, meeting, or file-sharing service; and every Google Drive address except a plain file (`/file/d/<id>`, stored without anything after the ID, never with `usp=sharing`). Removed secrets and skipped addresses count toward `flix_link_tokens_stripped`. Excluded sites (`FlixSiteExclusions`) are the person's list (host suffix on label boundaries) and, while **Leave out banking and health sites** is on, a built-in list of banks, payment services, brokers, insurers, tax and health portals, plus host labels containing banking or health words in English and German. The sidebar's **Links** (activity) and **Web documents** (kind) filters list them; both appear while tracking is on or links exist.

### Engines and fallbacks

- **Lookout** (`FlixSemanticIndex`) answers only while it runs (set up, on, started). Three narrow accessors on `LookoutEngine` serve it and change nothing the Hub shows: `embed(text:)` (the query encoder), `storedVectors(forPaths:)` (each file's segment vectors averaged, text segments preferred, at most 8 per modality, read from the store without loading the in-memory vectors; `Searcher.fileVectors`), and `contentMatches(for:limit:)` (Lookout's own hybrid search; a meaning search loads the vectors, which are released 120 s later unless the Files tab shows). Vectors are cached by path; "no vector" answers are dropped whenever Lookout reports new vectors.
- **Apple Intelligence** (`FlixLanguageModel`): a fresh session per call, guided generation into a `@Generable` type (never "answer in JSON"), greedy sampling, a timeout (3.5 s for search, 5 s for Smart Filters, 6 s for the morning card, 12–15 s in the background), silent failure. Pictures go to the model only when it reports `.vision`.
- **Tasks and routing** (`FlixAITask`, `FlixAIRouting`): every model call names its task. Each task has a cost (cheap: small bounded input, short answer; expensive: large input or real reasoning), a trigger (background: runs by itself per file, window, or day; on demand: only when asked), and whether its input stays on the Mac (files read in the background, the window in front, pictures checked by the guard). `FlixAIRouting.engine(for:cloudChosen:)` is the one place that picks an engine. Only an expensive, on-demand task whose input the person chose to share may use Claude (`mayUseCloud`); background tasks could add up to thousands of paid calls, so they never leave the Mac. Today that is Ask Robi alone, following Robi's own setting; every other task runs on Apple Intelligence.

| --- | --- | --- | --- |
| `searchUnderstanding`, `smartFilter` | cheap | on demand | no |
| `threadName`, `morningRecap` | cheap | background | no |
| `documentReading`, `pictureCaption`, `windowText`, `windowPicture`, `pictureSensitiveCheck` | cheap | background | yes |

- **Without Apple Intelligence**: search and Smart Filters use the rules; Threads keep folder or word names; no captions or renames; facts come from the deterministic extractor (English and German word lists) only, and the sensitive guard's rules decide alone.
- **`FlixSemanticScoring`** holds every threshold (related files 0.72 text / 0.82 pictures, folder fit 0.62 with a 0.03 margin, More like this 0.55 and z ≥ 0.8). They are first guesses, untuned. Fits this window uses it too, with its own lower floor (see [Matching](#matching)).

### Search in plain words

The panel debounces typing (420 ms); `FlixIntelligence` cancels the previous search. `FlixQueryModel` asks Apple Intelligence for `FlixGeneratedQuery` (activity, kinds, extension, days, minimum amount, folder, site, topic) and keeps only what the sentence backs: a folder, site, or amount must appear in it, and with a rules topic the model may only narrow it. Fields the model leaves empty come from `FlixQueryParser`, which knows English and German words for activity ("sent", "geschickt"), kinds, extensions, times ("last week", "gestern", "letzten 10 Tagen"), amounts ("over €1,000", "über 1.000 €"), places ("in Downloads"), and hosts.

`FlixQueryTokens` turns the fields into tokens, each a Smart Filter rule. A new rule, `.amountOver`, is answered from the totals the analysis read, through the same cached lookup as `.about`. `FlixSearchMatcher` applies every rule; the topic matches by name, or **by meaning** through the caption, the folders, the download host, or Lookout's content matches, which are also kept in `FlixTopicCache` so removing a token (which re-evaluates the rules) keeps the meaning matches. When nothing has every topic word, the search widens to any distinctive word in the name. A single word without Lookout is left to plain name search.

### Threads

`FlixThreadProvider` clusters the last seven days (files and folders, no apps, links, or noise; at most 300 items) off the main actor. Two items link within 72 hours when their Lookout vectors are related or their names share a distinctive word, or within 12 hours when they share a working folder that is not a catch-all one (home, Desktop, Documents, Downloads, Pictures, Movies, Music, iCloud Drive). Connected groups of three or more are threads; at most eight, 40 members each, newest first.

Identity: a cluster keeps the previous thread it overlaps most when they share at least a third of their members (Jaccard); otherwise it is named `thread-<oldest member's id>`. Threads are saved in `threads.json`. Names start as the most common working folder or shared word with an emoji for the kind; the provider's worker then asks Apple Intelligence (`FlixGeneratedThread`: name, emoji, summary) from member names, captions, and folders, one thread at a time, and again when fewer than 60 % of the members are the ones it named. The model also sees the names the other threads carry and is asked for one that tells this group apart ("Craft Anything icons" next to "Craft Anything"). Threads that still share a name, ignoring case, accents, and spaces, are shown as one (`FlixThreadProvider.displayThreads`): the newest keeps its identity, name, emoji, and summary, and the members are joined newest first, at most 40.

Names lead with what tells a thread apart, because the sidebar cuts them off after about 15 characters: the instructions ask for "Screenshots · Flix Files", not "Flix Files – Screenshots". When a name still starts like another thread's (the first 15 characters, folded), the model is asked once more with that start named. `FlixThreadNamer.version` (now 2) is saved with each name, and a thread named by an older version is named again once.

**Hide Thread** (the thread's context menu) takes it off the sidebar, with Undo in a toast; its files stay in the list, and a selected thread falls back to All. The flag is saved in `threads.json` and outlives later passes: a cluster that keeps the thread's identity keeps it hidden, and a hidden thread no cluster matched is kept while any member is still in the last seven days, so the same work cannot return under a new identity. Records shown as one with it hide with it. Hidden threads are not named again and are not offered to the namer as other names. There is no "clear all": the **Threads** switch in Settings turns the section off.

### Annotations

`FlixAnnotationProvider` answers every history pass quickly from caches and does its slow work in its own worker:

- **Versions** (`FlixVersionFamilies`): names that match once version marks are removed (`v3`, `version 2`, `rev 4`, `(2)`, final, signed, draft, copy, Fassung, Entwurf, unterschrieben…), of the same broad kind, with at least one mark. Cryptic names never form families. With vectors, a member clearly unrelated (cosine below 0.5) to the newest one leaves. Rank: signed > final > plain > draft, then the version number, then the date. Phase A's version pill and "newer version" question read the result.
- **Folder suggestions** (`FlixFolderSuggester`), for files directly in Downloads: the nearest centroid among folders holding at least two history items (outside Downloads, the Desktop, and home); without vectors, a folder whose name words all appear in the file's name or caption, then finance and picture folders.
- **Captions, renames, facts**: the worker reads at most 40 waiting files, newest first, one at a time, only paths `FlixReadPolicy` allows, never during a drag (`FlixSmartServices.waitWhileDragging()`, observation, no polling). `FlixContentReader` reads the first four PDF pages, 64 KB of text files, Office and RTF documents through AppKit's importers, Spotlight's page count, and a picture downscaled to 1,024 px; at most 6,000 characters. `FlixFactExtractor` finds due and valid-until dates, totals with currency, signature and paid wording, direct debit on a bill ("Wird abgebucht": nothing to pay by hand; not on bank statements), and page or slide counts, only in documents a person reads: data and code (JSON, XML, property lists, YAML, logs, configuration, source code) get no facts, since their dates are timestamps and their numbers sizes. English key words count only as whole words ("format" is not "form"); German stems, marked `*`, match inside compounds ("Stromrechnung"). Each chip's tooltip says what it is and that it was read from the file. Apple Intelligence reads every document a person reads (`FlixAITask.documentReading`: cheap, on the Mac, once per file version) and cryptic names (`FlixFileNaming.isCryptic`: screenshots, camera names, `document (3)`, hashes, digits). The model decides: `FlixGeneratedDocument` names the document's kind (`FlixDocumentKind`: invoice, receipt, quote, reminder, contract, bank or card statement, payslip, tax document, ID, letter, form, other), its payment state (open, paid, direct debit), due and valid-until dates, total, and signature state, each with the exact words it was read from. The text proves (`FlixDocumentReading`): a fact is kept only when its evidence appears in the text (case, accents, and line breaks ignored) and contains the fact itself (the same day; that amount with a currency, whose currency wins). Date evidence must also say more than the date (`FlixFactExtractor.saysMoreThanDates`): a bare "27.10.2026" is usually the document's own date. The model's reading then decides which facts apply: no due date once the payment is settled (proven paid or direct debit, whose chip says why), valid-until only on a quote or contract, and signature chips only on a contract, form, or quote; a signature chip no longer hides the payment chip. Without a reading, `FlixFactExtractor` is the fallback. The kind is stored with the analysis and settles the sensitive guard's verdict. `FlixGeneratedPicture` captions pictures. `FlixAnalysisRecord.currentVersion` 5 redoes every analysis made before; a record made while the model was ready (`modelConsidered`) is not asked again until the file changes. Captions and renames show only while the name is still cryptic; `FlixFileNaming.sanitizedName` keeps the extension, strips separators, colons, control characters, and leading dots, caps the stem at 80 characters, and numbers around names already in the folder.
- **Caching**: `analysis.json`, by path, invalidated by modification date and size, at most 3,000 records. A record made without the model is redone once the model is ready; a failed model call is retried after a day; an unreadable file gets an empty record until it changes. Renames and moves made in Flix Files carry their record along.
- **Sensitive flags and learned noise** are never set or cleared here: the previous values are kept (phase B1 owns the sensitive guard). Noise refinement is not implemented; `FlixNoiseRules` decides.

### Tidy

`FlixTidyProvider` lists items whose names are still cryptic and have a rename suggestion (captions on), or that sit directly in Downloads with a folder suggestion (folder suggestions on), at most 30, from the annotations already computed, so the sheet fills at once. `FlixPanelState.applyTidy` renames, then moves, and its one Undo moves each file back to its original path.

### Smart Filters from a sentence, and the filter tip

`FlixSmartFilterProvider` asks Apple Intelligence for `FlixGeneratedFilter` (name, emoji, kinds, activity, days, folder, site, topic); unlike search, the topic may widen the sentence ("tax stuff" → "invoices, receipts, budget") because it matches by meaning. A folder must be one the history uses. `FlixSmartFilterBuilder` makes the rules: when the topic names such a folder and nothing else constrains it, the filter matches that folder **or** the topic by meaning; otherwise every rule must hold. The proposal waits for Lookout's matches of its topic, so the sheet's count (now evaluated with the semantic lookup) and the new filter agree. Saved filters' `.about` topics are asked again in the background on history passes (`FlixSimilarityProvider.warmSmartFilters`, at most every ten minutes per topic).

The **filter tip** comes from drag memory's open counts: a working folder opened in the same part of the day (morning 5–12, afternoon 12–18, evening 18–24) on three different days of the last 14 earns one tip, offered once and never again, and never for catch-all folders or a folder that already has a location Smart Filter.

### Where was I?

`FlixMorningProvider` runs on the first open of a day (remembered in `flix.morning.lastShownDay`, so a relaunch doesn't repeat it), when the last day with activity is at most four days back and had at least three items. Apple Intelligence writes one or two sentences from the threads' names, summaries, and member names; a message naming none of the threads is dropped for the fallback, which names up to two threads or the newest file. Actions: **Reopen** the main thread's files (at most ten) and show the second thread. Debug builds add **Settings → Flix Files → Debug → Show Again** (`FlixDebugCard`, `FlixIntelligence.resetMorningCard()`), which clears the remembered day and the session's own once-a-day check so the next open asks again.

### More like this

`FlixSimilarityProvider.similar` ranks history items by their Lookout vectors against the item's own (like with like), at most 12. Without a vector it falls back to the same kind with a shared name word, then the same folder and kind. It stays inside the history.

### Drag memory

`FlixDragMemoryProvider` counts each accepted drop out of the panel by file kind (`pdf`, `image`, `spreadsheet`, …) against the app that was in front when the panel opened (bundle identifier). Rows then show "↺ you've sent PDFs here before" while that app is in front; after three drops of one kind, a toast says what Flix Files noticed (right away when the panel stays open, otherwise on the next open). `FlixIntelligence.likelyItem(for:among:)` names the newest item of the kind usually sent to the app in front; it breaks ties in the Fits ranking and sets `predicted` on `flix_drop`. Tile drags carry no context and are not counted. **Forget** empties `memory.json`, drops and opens alike.

### Ask Robi

`FlixRobiProvider` follows Robi's own answer model. With Claude, the key is read from the Keychain only when a question is asked; with no key the answer is "Add a Claude key in Robi settings to ask about files." With the on-device model, the answer is made on the Mac and the sheet says so. Suggested questions depend on the selection: totals and due dates for invoices, what changed for versions, what is shown for pictures, otherwise summarize, what they share, and a draft message. At most six files are read, 12,000 characters each for Claude and 1,500 for the on-device model, plus one picture per image for Claude (Vision text for the on-device model); protected folders DOKK may not read contribute only their name. `RobiAgent.answer(question:about:model:update:)` (`Robi/Answering/RobiFileQuestion.swift`) is the narrow entry point: no tools, files quoted as untrusted data, at most four pictures, 700 answer tokens, and AI observability with `includesContent: false` and a closed error code (`AIObservability.ErrorCode`). The localized message the sheet shows never goes to observability: a Claude error's text can carry a server message or a host name.

### Checks by hand

The [acceptance checklist](ACCEPTANCE.md#phase-b2-intelligence) lists them. The thresholds above and the AI prompts need tuning against real files; none of it has run yet.

## Settings

**Settings → Flix Files** is its own section under Features, like Lookout and Plugins:

- **Flix Files** on or off. Off removes the tile, the menu bar item, and the shortcut, stops every source and observer (Spotlight, the folder watcher, the front-window observer, link tracking, site icons), and cancels every background pass and worker (annotations, Threads naming, Smart Filter warming, the sensitive guard, conversions, the tile's count, Save this page); nothing of it starts at launch while off. The providers' caches stay for when it is turned back on.
- **Where it lives**: Show in the dock (on), Show in the menu bar (off), Keyboard shortcut with a recorder (Control-Option-Command-F). The recorder needs Control, Option, or Command (function keys excepted), refuses DOKK's own shortcuts and app-wide commands, and warns about Spotlight's and launchers' combinations. An orange row appears when another app holds the combination. Recording pauses the shortcut so pressing the current combination records it.
- **When Flix Files opens**: Do nothing, Copy newest, or Copy its path. **After you drag something out**: Close or Stay open.
- **Flix Pick** (on): the switch, a note while DOKK lacks Accessibility permission, and the apps hidden with **Not in**, each with **Show Again**. See [Flix Pick](#flix-pick).
- **What it tracks**: Files you open, New, saved, and downloaded files, Folders, Apps, and the watched folders with their access and **Allow…**.
- **Web links**: Track web links (off), Pages you read (off, its own opt-in), Leave out banking and health sites (on), Load site icons (off), and sites never tracked. While tracking is on, a note explains Safari's limit, and another appears without Accessibility permission.
- **✦ What powers it**: Lookout, Apple Intelligence, and Robi status, read without starting anything and kept current by `FlixEngineMonitor` through Observation (Lookout's settings and running state, `SystemLanguageModel`'s availability, Robi's chosen model and key; no polling). The Robi row follows Robi's own choice: **On this Mac** when Robi answers with Apple Intelligence (no key needed), **Claude** when a key is saved, **Not set up** when Claude is chosen without a key. Suggest files for the window in front, Show "fits here" on the tile, and the Helpers (captions, Threads, folder suggestions, sensitive guard, hide noise, drag memory with **Forget**). The window, tile, and sensitive switches drive phase B1's work; captions, Threads, folders, and drag memory drive phase B2's providers (see below).
- **History**: the item count and **Clear History…** (files, Favorites, and Smart Filters stay; nothing from before the clear comes back, see [Data](#data)).

Search finds the section by its name and keywords such as downloads, screenshots, shortcut, and web links.

## Privacy

- The history stays on the Mac, in DOKK's Application Support folder. Nothing leaves the Mac except a site icon request while **Load site icons** is on, and Ask Robi when Robi uses Claude.
- Spotlight metadata needs no permission. Protected folders are read only after you allow them, from a button you press. The sensitive guard and conversions read only what that policy allows.
- Window reading needs Accessibility (text) and Screen Recording (a picture of that one window); Flix Files never asks for either and skips the step without it. The picture and the text stay in memory for that reading; only the demand derived from them is cached, until the window changes. Apple Intelligence runs on the Mac, and these calls are not sent to AI observability.
- A download's page is stored on its file's row only while web links are on, the site is not excluded, and the link tracker verified the download came from a normal window showing that page; otherwise only its host is kept for the row, and for an excluded site not even that. Pages stored by earlier builds without that verification are scrubbed to their host at launch. A download becomes a link row under the same rule (see [Web links](#web-links)). Link tracking stores only the address (no query, fragment, or sign-in details; nothing for a credential-bearing address), title, browser, and time, never a private or unknown window, never an excluded site, and never page contents.
- The sensitive guard keeps a verdict per file path in `sensitive.json`, and the paths you marked **Not Sensitive**.
- Ask Robi sends only the files you ask about, with your question, only when you ask, and only when Robi's settings choose Claude with your key; with the on-device model nothing leaves the Mac. Captions, Threads, facts, search, Smart Filters, and the morning card use Apple Intelligence on the Mac and Lookout's local index.
- Every Flix Files model call reports metadata only to AI observability (`AIObservability.capture(…, includesContent: false)`): span name, model, latency, token counts, and a closed error code. Prompts, file names, file contents, answers, and error text are never captured: with `includesContent: false`, `AIObservability` replaces any free-form error with a code itself, so no caller can leak one.
- What Flix Files learns stays in its Application Support folder: `analysis.json` (captions, names, facts by path), `threads.json` (thread names and members), and `memory.json` (drop counts by file kind and app, opens by folder and part of the day, and Flix Pick's picks by app and path). **Forget** empties `memory.json`.
- Flix Pick reads only windows and sheets whose `AXIdentifier` is `open-panel` or `save-panel`; to find one it looks only at the focused window's identifier and its direct children's roles. It never asks for Accessibility. See [Flix Pick](#flix-pick).
- Analytics count feature use without names, paths, URLs, hosts, contents, query text, AI prompts or answers, app names, bundle identifiers, or window titles. Apps and pages reach analytics as categories only (see [Analytics](#analytics)).

## Known limitations

- A URL dragged from a browser onto the **tile** is not kept; drop it on the panel. The dock's drop routing reads file URLs only.
- macOS does not reveal a drop's destination app, so the sensitive and version questions run at drag start and stop the drag; you drag again after answering. A flagged file is therefore asked about on every drag, also into Finder, until you answer **Not Sensitive** or within 30 seconds of an answer to that question.
- The stale-row check at the Trash and at moving folder and drive tiles compares identities with `lstat`, then acts with another call, so a file swapped in the instant between them is not caught. Hub Files panes and Vapor do not compare identities (Vapor shows the pile before anything is deleted).
- Background readers hold what they read in memory, up to each use's cap; a picture or PDF over 64 MB gets no caption, and one over 60 MB is not checked by the sensitive guard.
- Folder names on rows and in menus come from the path. Desktop, Documents, and Downloads show their localized names only once Flix Files may read them; until then their English names show.
- The tile's ✦ pill follows window and title changes only with Accessibility permission; without it, only app switches refresh it. A page that changes its address without changing its title (some single-page apps) is not noticed until the next title change, for the pill and for web links.
- A conversion starts when the window's limits are known (the panel's reading or the tile's count). A row dragged before its copy is ready goes out unchanged. Copies of rows beyond the first six and the selection are not made ahead.
- Converted PDFs from text use Core Text, and Markdown is laid out as written, syntax included. Word, OpenDocument, RTFD, Pages, Numbers, and Keynote files are not converted at all, so a portal that takes only PDFs gets them unchanged. The RTF check reads control words, a best-effort list: a construct it does not know that the importer drops would still be lost. A file the converter declines can still show in Fits (the ranking runs before the copies are made), without a chip, and goes out unchanged.
- The fallback rules read English and German. Other languages need Apple Intelligence to find what a window asks for.
- Safari has no private-window signal DOKK could verify, so Safari pages are kept only by deliberate saves and URL drops, and Safari downloads never become link rows. The private-window checks for Chromium and Firefox browsers rely on visible labels in a fully read toolbar and have not been verified by hand, including in other UI languages; a label DOKK does not know would make a private window look normal. A browser whose address field is not inside an `AXToolbar` is never tracked automatically.
- macOS does not say whether a download happened in a private window. A download's page is kept (on its row and as a link row) only when it arrived within two minutes while a normal window of an automatic-tracking browser showed that very page; a private window downloading in the background while a normal window shows the same page could still be credited to it. A download from a page you already left, or one without a referring page, keeps only the host.
- The invitation and share-link list (`FlixShareLinkDenylist`) is best-effort and maintained by hand; an invitation format it does not know is caught only by the general rules (credential route words, secret-looking segments).
- Stored addresses lose their whole query, so pages that differ only by query (a video's `?v=`, a search's `?q=`) share one link row.
- Undo of a move, rename, or Tidy checks the moved file's identity (volume, inode, and for files size and modification time). A file edited after the move is therefore not moved back, by design; the toast says which items were left.
- Trash, Move, Rename, and Tidy refuse once for a file saved since it was listed (most apps save by replacing the file), and for a row whose identity was not read yet; the second attempt acts on the file as it is. The check and the operation are separate calls, so a replacement in the instant between them is not caught.
- The read policy is re-checked when a background read opens a file, and direct reads cannot follow a link (`O_NOFOLLOW_ANY`). Quick Look thumbnails, icons, file stamps, folder listings, and RTFD packages take the path resolved right before the call, so a link swapped in during that call itself is not caught.
- The sensitive guard checks at most 300 files per history change and reads the newest first; a large backlog takes several changes to finish. A file it cannot read (a protected folder not allowed) is never flagged.
- Fits matches by meaning only while Lookout runs and only for files Lookout has read; pictures and files outside Lookout's folders match by words. The blend's numbers (0.30, 0.55, z ≥ 1.0, 0.6) are first guesses.
- A folder granted once and later reset with `tccutil` still counts as allowed, so the watcher could then make macOS ask again. Remove and re-add the folder to reset what DOKK remembers.
- Items moved or renamed outside Flix Files keep their old path until Spotlight or the watcher reports the new one; the old row stays until removed.
- App activations are recorded at most every five minutes per app, so a quick switch back does not move the app up.
- `FlixShortcutCombo` names keys from the current keyboard layout when the recorder draws them; a layout change shows the new layout's character for the same key.
- Phase B2's similarity thresholds and prompts are untuned first guesses.
- Captions, facts, and renames exist only for files in folders DOKK may read (allowed watched folders and Lookout's folders). Spreadsheets' sheet counts and Keynote or Pages text are not read; their page or slide count comes from Spotlight when it has one.
- The filter tip counts each item's latest open only, so opens between two history passes of the same file count once. Tips are folder-based; Thread-based tips are not implemented.
- The analysis worker runs one file at a time; a large first history fills captions over minutes, newest first.
- Analytics' drop target is the app whose window is under the drop point when the drag ends; a drop that lands on a window behind a floating one, or on the Desktop through a gap, can be attributed to the wrong app. A browser drop's page kind is known only when the panel read that browser's window for Fits this window.

## Flix Pick

Flix Pick (DEE-164) is a slim rail beside another app's Open or Save picker that lists the files (Open) or folders (Save) the app most likely wants. The approved design is [`mockups/flix-pick.html`](mockups/flix-pick.html), style **Tuck**: a 58-point rail of icons, 8 points beside the picker and 8 below its top, that springs open to 272 points on hover. Click selects in the picker, ⌥-click and double-click also press its default button, and a row can be dragged in. How it behaves for a person is in the [guide](GUIDE.md#flix-pick).

### Detection

`FlixPickObserver` follows the frontmost app (NSWorkspace activation, a 120 ms settle) and moves one `FlixPickSession` to it on `FlixAXThread`. The session's `AXObserver` listens on the app element for window created, focused window changed, main window changed, and `AXSheetCreated`; each burst is coalesced for a few milliseconds and the focused window is checked: a picker is a window (subrole `AXDialog`) or an `AXSheet` child whose `AXIdentifier` is exactly `open-panel` or `save-panel`, in the app's own process even when it is sandboxed. While a picker has focus the session adds destroyed, moved, and resized on the picker (and on its window for a sheet), selected rows changed on the picker and its list, value changed on the folder popup, and focused element changed on the app, which notices a sheet that closed without being destroyed. Nothing polls. The main actor hears about it through `FlixPickEvent` values in order (`DispatchQueue.main`); the elements never leave the thread. DOKK's own process and the apps listed under **Not in** are never observed.

Inside the picker, `FlixPickAX.controls(in:)` finds `OKButton`, `CancelButton`, `ListView` (the list view's `AXOutline`), `ColumnView` (`AXBrowser`), and `where popup` by identifier, walking at most 400 container elements and never into lists, tables, browsers, or rows. A file row is an `AXTextField` whose `AXURL` is the file's URL. Every identifier is looked up; a missing one leaves its route out.

### Routes into the picker

`FlixPickRouter` tries, cheapest first:

1. **Already there**: exactly that file is selected (a multiple selection never counts), or the picker's first listed row is inside that folder. The folder popup's name is never taken as proof of a folder's place.
2. **Listed row** (Open pickers with a list view): when the first row shows the file's folder, the rows (at most 300, within 0.8 s) are matched by `AXURL` and the list's `AXSelectedRows` is replaced by that one row, then read back. Measured at about 70 ms, nothing on screen.
3. **Go to Folder**: ⇧⌘G opens the sheet, and Return is used only as the last way to send it on. It waits up to two seconds for every modifier to be released (the ⌥ of an ⌥-click would make it ⌥⇧⌘G); then, in one block on the Accessibility thread, it checks that the picker exists and is the focused window or its sheet, and last, with nothing read after them, that the session is still attached to the app the action started in, that app has keyboard focus (its own application element's `AXFrontmost`, which carries the messaging timeout; the generation is checked again after that lookup), no modifier is held, and Secure Event Input is off, and posts to the HID event tap (`CGEventSource(stateID: .hidSystemState)`; posting to the app's process does not work). It then waits up to 1.2 s for the focused element to be this picker's `PathTextField`, sets its `AXValue` to the full path, and sends the sheet on, in this order: the field's `AXConfirm` when it offers one, else the Go to Folder sheet's `AXDefaultButton` when that sheet is not the picker and the button is not `OKButton`, else Return (the probe's route, which worked every time on macOS 27). The way is chosen first; then, whichever it is, the same final checks run in the same block right before it, with nothing else read in between: the picker is focused, the app's focused element is still this picker's `PathTextField` and its value is exactly the path, the attachment generation is unchanged, and the app has keyboard focus (for Return also no modifier held and Secure Event Input off). When any check fails, the sheet stays open with the path typed, for the person to send on. When the sheet does not close (the path is gone), it is dismissed with the field's `AXCancel` or the sheet's `AXCancelButton` (never `CancelButton`, never Escape), or left open when neither exists. For a file path macOS selects the file. 0.1–0.4 s; the sheet flashes.
4. **Confirm** (⌥-click, double-click, or a double-click that arrives while the click's jump runs): the router waits up to 800 ms for the picker to show exactly that file or that folder's rows, then one Accessibility block finds the controls and reads whether `OKButton` is enabled, and only after that, with nothing else read in between, makes the final checks: the picker focused, exactly that one file selected (Open) or the first listed row inside that folder (Save), the attachment generation unchanged (checked again after the keyboard-focus lookup), and the app holding keyboard focus. For Open the very last read, right before `AXPress`, is the selected rows again, which must still be that same single row element, so a ⌘-click in between cannot add a second file. A Save picker keeps its typed name. An empty folder (no row to prove where the picker is), or a picker without a list view (column or icon view), is moved to but never confirmed.

Every Accessibility call carries a 0.25 s messaging timeout, set on each element before it is queried, and each walk (finding the picker among a window's sheets, the controls, the rows, a row's cells, a field's ancestors) also has a deadline, so a picker on a stalled network folder cannot hold the shared thread for long.

The picker closing cancels the running action. A drag uses `FlixDragSession` with the row's file; a drop inside the picker's frame counts as used.

### Ranking

`FlixPickCandidates` builds the rows from Flix Files' history (the newest 800 rows), drag memory, Threads, and earlier picks; `FlixPickRanker` scores them. Open pickers: files whose type fits the app (`FlixPickDocumentTypes`: `CFBundleDocumentTypes` with role Viewer or Editor, `LSItemContentTypes` or `CFBundleTypeExtensions`, and the app's imported and exported type declarations; a catch-all or no declaration lists any file; folders only when the app declares them), plus files picked there before that the history no longer lists. The picker itself cannot help: `AXEnabled` is true even for the rows it greys out. Save pickers: folders the person saved to through this app's picker, folders holding recent files that fit the app's editor types (14 days), folders where files were saved or created in the last three days, and folders opened lately; only folders in the home folder (not Library, except iCloud Drive and cloud storage) or on other volumes, never hidden ones or packages. Links, apps, noise, and files the sensitive guard flagged are never suggested; earlier picks are filtered by the same standardized paths and by the sensitive guard's cached verdict for the path itself (`FlixSensitiveGuard.verdict(forPath:)`), so a flagged file picked before cannot come back through them, even after its history row was removed.

Scores add up: picked here (30 + 10 per pick up to six, plus up to 10 decaying over two weeks), part of the same Thread as this app's latest pick (22), new in the last two days (14 to 22), kinds dragged to this app (8 + 2 per drop up to five), recent fitting files in a Save folder (10 + 4 per file up to five), and recency (20, halving roughly every two days). The largest part names the reason line: learned green, context purple, new orange, used blue; "fits" when nothing stands out. The weights are first guesses. Up to ten are ranked, files that are gone are dropped where the read policy lets DOKK look (others are kept rather than read), and the best five show. With no row, no panel appears, but the picker is still followed so a pick there is learned.

### Learning what was picked

macOS reports no button press, and the picker is gone when its destruction is reported, so `FlixPickClosing` counts only what it can tell for sure. A global mouse-down monitor (location and click count only, never keys) runs while a picker is open, matched against the frames of `OKButton`, `CancelButton`, and the list, which the session reads at discovery and on resize and shifts on a move. A press on `CancelButton` within 1.5 seconds of the close, and after any confirm of Flix Pick's own, is a cancel and wins. Flix Pick's own press of the default button counts its file or folder only with positive proof that it closed the picker: the Accessibility thread takes the press time right after `AXPress` succeeds, and the picker's destruction (`kAXUIElementDestroyedNotification`, or an "invalid element" answer, never a timeout) must come within 0.6 seconds of that time, with no sheet appearing in the app in between (a "Replace?" prompt). The session puts that press time on the close event; the coordinator credits the press only when it matches the press its action reported, and a close reported before the action reported waits for it, so neither order loses or invents a pick. A close within 1.5 seconds of a press on `OKButton`, or of a double-click in an Open picker's list, counts the last selected file (Open, only when exactly one is selected) or, for Save, the folder its listed rows were in at that press, read by full path the moment the mouse went down (an empty folder, or a read that came too late, learns nothing; the folder's name is never used). Anything else, including Return and Escape, is unknown and learns nothing, so a cancel is never counted and a keyboard confirm is missed. Picks are stored per bundle identifier and path in `FlixDragMemory.picks` (`memory.json`), at most 40 paths per app and 60 apps, the least recent going first; only while **Learn where I drag things** is on, and **Forget** clears them. A picked file found gone is forgotten.

### Panel

`FlixPickPanelController` owns a borderless non-activating `NSPanel` that refuses key and main, at floating level, on every Space and beside full-screen apps, never hidden on deactivate. A click in it leaves the app frontmost and its picker focused. Placement is pure (`FlixPickPlacement`): Accessibility frames are converted with `appKitY = primaryMaxY − axY − height`; the side is chosen with the open width, so it flips to the left of the picker when the open rail would leave the visible frame of the picker's display, and it is pushed up above the Dock. The window always matches the body: opening widens the window first (the edge next to the picker stays put) and then springs the body open; closing springs it shut and then narrows the window. Content is laid out at the open width and clipped, so nothing reflows; the text fades in after the width starts to grow and out just before it shrinks. The header keeps the rows' columns: the logo is centred over the icons, which is all the closed rail shows, and the title starts where the file names do (`FlixPickStyle`). A row's highlight is as wide as the rail shows, a click flashes it for 160 ms, it stays tinted while its action runs, and it dims while it is dragged. The timings are in `FlixPickMotion`; every animation starts from a state change, none from pointer moves. Hit testing ignores the shadow margin. The rail closes 280 ms after the pointer leaves, unless the ⋯ menu, a drag, an action, or a footer note keeps it open. With Reduce Motion the panel only fades, the rail changes width at once, and rows do not scale when pressed; Reduce Transparency draws the solid surface (`FlixPanelGlass`, here with a 14-point corner and a shorter shadow). It hides when the picker closes or loses focus, its app moves to the back, the displays change, or the Mac sleeps; after a display change it stays hidden for that picker.

### Limits and what was not exercised

- The identifiers (`open-panel`, `save-panel`, `OKButton`, `CancelButton`, `ListView`, `ColumnView`, `where popup`, `PathTextField`) are macOS's private structure, proven by two probes on macOS 27. Another macOS version may change them; Flix Pick then finds nothing or falls back to dragging.
- Not exercised: pickers in Chrome and Electron apps, row selection in column and icon view (Go to Folder is used, and confirming is skipped), multiple displays and displays with negative origins, full-screen apps, and Spaces. Nothing of Flix Pick has run in the app yet; the routes and timings come from the probes.
- Keyboard closes are not learned; a Save picker's folder is learned only from a mouse press on its Save button (or Flix Pick's own) while its rows show where it is, so a save into an empty folder is not learned.
- Context from the window behind the picker (the document it belongs to) is not read: that would mean reading a window that is not a picker. The purple reason comes from Flix Files' Threads instead.
- A file in a protected folder DOKK may not read is never checked for existence, so a deleted one can still be listed; Go to Folder then fails and the footer says to drag instead.

## Analytics

PostHog only, through DOKK's typed `AnalyticsEvent` (no Sentry). The events, counters, and person properties are listed in [`ANALYTICS.md`](ANALYTICS.md#flix-files); the vocabulary lives in `DeeDock/Analytics/Events/AnalyticsFlixEventTypes.swift`, and the reductions from Flix Files' models in `Flix/Analytics/FlixAnalyticsMapping.swift`.

- **One session per open.** `FlixSessionMetrics` begins right after `FlixPanelState.prepareForOpen` (trigger, placement, display, front app category, unseen count, list size) and ends first thing in `FlixCoordinator.close(restoreFocus:animated:reason:)`, so exactly one `flix_session_ended` leaves per open. The panel's commands (`FlixPanelState+Commands`) report each action with where it came from (`FlixActionOrigin`: a list row, a Fits row, a thread card, the morning card); the place is read at that moment as a section and a 1-based rank. Keyboard commands use the place the selection was made in. `FlixPanelController` reports mouse presses inside the panel (for `keyboard_only`) and the first frame (for the open-latency counters). The close reason comes from the route: Escape, a click away or another app (also the tile or menu bar item clicked again), the shortcut again, or anything else.
- **Visits inside a session.** A search starts with its first word and ends when the field is emptied or closed, a result is opened or dragged, or the panel closes; it reports the word count, the understood tokens' types, the parser (`FlixSearchReport`), and the result count, never the sentence. More like this ends the same way. A morning card that was on screen and not answered reports `ignored` when the panel closes.
- **Drops.** An accepted drag out reports `flix_drop` with the source, the first item's place (read when the drag started), the kinds, the conversion (`FlixDragPlan.convertMs`), any answered drop question, and the destination: what DOKK's dock received (`DockDragCoordinator.flixDropLanded`), else the category of the app whose window is under the drop point (`FlixDropTargetResolver`). Closing a drop question without an answer reports a cancelled drop. Drops on a sidebar favorite report `favorite_folder` or `favorite_app`.
- **Categories, not identities.** Apps become `FlixAppCategory` (Launch Services' web and mail handlers, then `LSApplicationCategoryType`); pages become `upload_form`, `web_document`, `webmail`, or `other_page`; watched folders become desktop, documents, downloads, iCloud Drive, or other; the shortcut becomes a token such as `ctrl_opt_cmd_f` built from the key code by position, which `AnalyticsShortcutCombo(rawValue:)` refuses unless it fits that grammar.
- **Settings.** `FlixSettingsStore` reports every change as `setting_changed` with `area = flix`, from `FlixSettings.analyticsProperties`: the reflected model with the watched folders and excluded sites as `watched_folder_count` and `excluded_site_count`, and the shortcut as `shortcut_customized` and `shortcut_combo`.
- **AI observability.** Every `FlixLanguageModel` call and Ask Robi (`RobiFileQuestion`) capture with `includesContent: false`: model, latency, token counts, and an error type only. The window interpreter (`FlixDemandInterpreter`) and the sensitive scanner's picture check capture nothing. `flix_robi_asked` reports which question (a suggestion's position or typed), the selection's size and kinds, the latency, and the result, never the question or the answer.

Nothing in Flix Files' analytics has been sent from a running app yet; the tests in `DeeDockTests/Flix/FlixAnalyticsTests.swift` cover the names, properties, reductions, and the session rules.
